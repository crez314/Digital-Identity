# 선행기술 지형과 청구 전략

> 변리사님께 가장 먼저 보여드릴 문서입니다. 청구범위를 어디에 두어야 하는지에 대한
> 판단 근거이며, **피해야 할 청구 방향**을 먼저 정리했습니다.

작성일 2026-09-02 · 조사 범위: 공개 학술문헌 및 공개특허 개괄 조사
**정식 선행기술조사(FTO/특허성)는 별도로 수행해야 합니다.** 이 문서는 방향 설정용입니다.

---

## 1. 결론 먼저

**"얼굴 임베딩의 코사인 유사도로 신원 일치도를 측정한다"는 것만으로는 신규성을 얻기
어렵습니다.** 이미 학술계 표준 평가 지표입니다.

| 이미 널리 쓰이는 것 | 근거 |
| --- | --- |
| ArcFace/CosFace/FaceNet 임베딩의 코사인 유사도로 identity similarity 산출 | 얼굴 교체·신원 보존 영상 생성 논문의 표준 평가 지표 (Face-Sim, ID similarity) |
| 프레임별 유사도의 **분산**으로 시간적 안정성 정량화 | 영상 얼굴 교체 평가에서 통용 |
| DINO/CLIP 특징으로 subject consistency·background consistency 측정 | 영상 생성 벤치마크의 표준 항목 |
| 딥페이크 탐지 | 국내 등록특허 존재 (예: KR102685693B1 딥페이크 비디오 탐지) |

따라서 **독립항의 중심을 "유사도 산출"에 두면 거절 위험이 큽니다.**

## 2. 차별화가 가능한 지점

기존 문헌은 대부분 **측정에서 끝납니다.** 벤치마크 점수를 내는 것이 목적이므로
"그래서 어떻게 고칠 것인가"가 없습니다. CREZ의 구조는 여기서 갈립니다.

| # | 차별 요소 | 왜 다른가 |
| --- | --- | --- |
| **A** | **폐루프 제어** — 검출 → 오류 유형별 전략 선택 → **부분 재생성** → 재검증 → 이력 축적 | 평가 지표 문헌에는 교정 루프가 없다. 생성물을 고치는 제어 구조다 |
| **B** | **오류 인물·구간의 특정** | 기존 지표는 영상 전체 또는 단일 인물의 평균값. 다중 인물 중 *누가* *언제* 틀어졌는지 특정하지 않는다 |
| **C** | **두 종류 신호의 분리 판정** — 기준 대비 하락(reference-to-frame)과 프레임 간 변화(frame-to-frame)를 별개 현상으로 취급하고 사유를 기록 | 분산은 흔들림만 본다. 기준과 꾸준히 다른 경우(대응 오류)와 기준과는 맞으나 튀는 경우(생성 불안정)를 구분하지 않는다 |
| **D** | **결정론적 전략 사다리 + 동일 전략 재시도 금지 + 무개선 시 승격** | 무작위 재시도가 아니라 오류 유형에서 조건 변경을 유도하고, 루프 종료를 보장한다 |
| **E** | **드리프트를 가중합이 아닌 감점항으로 분리** | 평균이 높아도 치명 구간이 있으면 사용 불가라는 판단을 점수 구조에 반영 |
| **F** | **판정 기준의 외부화·버전 기록** | 어떤 기준으로 판정했는지가 결과에 봉인되어 재현·감사가 가능 |
| **G** | **얼굴 신호 부재 시 신체 신호로 대체하고 결측 가중치를 재분배** | 결측을 0점 처리하지 않는다 |

**가장 방어력이 높은 조합은 A + B + D입니다.** 즉 *"다중 인물 중 기준 미달 인물과
시간 구간을 특정하고, 그 오류 유형에 대응하는 조건 변경을 적용해 해당 부분만
재생성한 뒤 재검증하는 폐루프"*.

## 3. 청구 방향 권고

### 3-1. 독립항에 반드시 포함해야 할 것

폐루프의 각 단계가 **하나의 청구항 안에서 연결**되어야 합니다. 단계를 쪼개
별개 청구항으로 두면 각각은 선행기술에 걸립니다.

```
기준 인물 참조정보 생성  →  신원 특징정보 추출  →  대응
   →  일관성 정보 산출(2종 신호)  →  기준 미달 인물·구간 검출
   →  오류 유형에 따른 생성 조건 변경  →  해당 부분만 재생성  →  재검증
```

### 3-2. 독립항에서 피해야 할 것

- ❌ "얼굴 임베딩의 코사인 유사도를 산출하는" 것 자체를 요지로 삼기
- ❌ "프레임별 유사도의 분산을 계산하는" 것을 요지로 삼기
- ❌ 특정 모델명(ArcFace, SFace, YuNet 등) 기재 — 회피 설계를 쉽게 만들고 권리범위를 좁힌다
- ❌ 특정 수치(0.64, 0.652 등)를 독립항에 기재 — 종속항이나 실시예로 내릴 것

### 3-3. 모델 비종속 표현

명세서 전반에서 기능적 표현을 사용합니다.

| 쓰지 말 것 | 쓸 것 |
| --- | --- |
| SFace, ArcFace | 신원 특징정보 추출부 |
| YuNet | 객체 검출부 |
| ByteTrack | 객체 추적부 |
| Hungarian 알고리즘 | 전역 최적 대응부 (종속항에서 "1:1 최적 할당" 정도로 한정 가능) |

구현이 인코더 인터페이스로 추상화되어 있어 이 표현이 명세서와 실제 코드에서
일치합니다(§7.5 인코더 인터페이스). 이는 실시가능요건 대응에도 유리합니다.

## 4. 실시가능요건 관련 — 정직한 상태 보고

특허법 제42조 제4항의 기재요건 관점에서, **현재 구현되지 않은 부분이 있습니다.**
변리사님이 명세서에 어떻게 기재할지 판단하실 수 있도록 그대로 적습니다.

| 청구하려는 요소 | 구현 상태 |
| --- | --- |
| 기준 인물 참조정보 생성 (이상치 제거·품질 가중) | 구현·검증 완료 |
| 신원 특징정보 추출 (얼굴/신체 독립) | 구현·검증 완료 |
| 대응 (전역 최적 할당 + 확정 보류) | 구현 완료 |
| 일관성 정보 산출 (2종 신호) | 구현·실측 완료 |
| 기준 미달 **구간** 검출 | 구현·실측 완료 |
| 기준 미달 **인물** 특정 | 구현 완료 (다중 인물 실측은 미완) |
| 오류 유형별 전략 결정 | 구현 완료 |
| **세그먼트 단위** 부분 재생성 | 구현 완료 |
| **인물 단위** 조건 변경 재생성 | **미구현** — 대상 인물 식별자가 생성 요청에 반영되지 않음 |
| 재검증 및 결과 분류 | 구현 완료 |
| 다중 인물 동시 생성 실증 | **미실증** — 실측은 1인 기준 |

**판단이 필요한 지점**: 미구현 부분을 청구범위에 포함할지 여부입니다. 특허는 실제
제품 완성을 요구하지 않고 통상의 기술자가 실시할 수 있을 정도의 기재를 요구하므로
포함이 불가능하지는 않습니다. 다만 **무효 공격의 표적**이 될 수 있으므로,

- (안1) 인물 단위 재생성을 **종속항**으로 두고 독립항은 "기준 미달 객체가 포함된
  구간을 재생성"으로 기재 — 현재 구현과 일치
- (안2) 출원 전 인물 단위 재생성을 구현해 실시예를 보강 (1주 이내 가능)

중 선택하시길 권합니다. 저는 **안2 후 안1 병행**이 가장 안전하다고 봅니다.

**출원 전까지 공개하지 마십시오.** 벤처 심사·투자 IR에서 기술을 설명할 때도
공개 범위에 주의가 필요합니다. 부득이 공개했다면 **공지예외주장(12개월)** 을
출원 시 반드시 신청해야 합니다.

## 6. 출원 범위 제안

| 구분 | 권고 |
| --- | --- |
| 우선 출원 | 국내 특허 출원 (KR) |
| 청구항 유형 | 시스템 + 방법 + 컴퓨터프로그램(기록매체) 3종 독립항 |
| 해외 | PCT 국제출원을 12개월 내 검토. 미국은 §101(추상적 아이디어) 대응이 필요하므로 "생성 조건을 변경해 재생성한다"는 **기술적 개선·제어** 성격을 명세서에서 강조 |
| 병행 | 판정 임계값·가중치의 구체적 수치는 **영업비밀로 유지**하고 명세서에는 산출 *방법*만 기재 |

## 7. 변리사님께 드리는 질문 목록

1. 독립항을 폐루프 전체로 구성할 때, 단계 수가 많아 권리범위가 과도하게 좁아지지
   않는지 — 어느 단계까지 필수 구성으로 둘지
2. 미구현 요소(인물 단위 재생성)를 청구할지, 구현 후 출원할지
3. 미국 진출을 전제할 때 §101 대응을 위해 어느 표현을 지금부터 넣어둘지
4. 판정 임계값을 명세서에 수치로 넣을지, 산출 방법만 기재할지 (영업비밀 균형)
5. 발명자 표시 — 착상은 사람, 구현 코드 작성에 생성형 AI를 활용한 상황의 처리
