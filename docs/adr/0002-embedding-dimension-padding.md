# ADR 0002 — SFace 128차원 임베딩을 vector(512)에 패딩 저장한다

- 상태: 채택
- 일자: 2026-09-01
- 관련: 기술명세서 §4.2, §7.1, §7.2

## 맥락

명세서 §4.2는 `identity_embedding.vector`를 `vector(512)`로 고정하고,
"모델 교체 대비 dim 컬럼 병행 관리"를 명시한다.

그런데 §7.1에서 확정한 얼굴 임베딩 모델 SFace(Apache 2.0)의 출력은 **128차원**이다.
스키마의 512와 맞지 않는다.

## 선택지

1. 컬럼을 `vector(128)`로 바꾼다 — 명세서 스키마를 변경해야 하고, 512차원 모델로
   교체할 때(§7.2 Phase 2 실측 후 상용 모델 검토) 다시 마이그레이션이 필요하다.
2. 모델별로 컬럼을 나눈다 — 테이블이 모델 수만큼 늘어난다.
3. 512로 두고 128차원 벡터의 뒤를 0으로 패딩한다.

## 결정

3번. `vector(512)`를 유지하고 `models.pad_to_storage_dim()`으로 패딩한다.
실제 차원은 `dim` 컬럼에 기록한다 — 명세서가 dim 컬럼을 둔 이유가 정확히 이것이다.

## 근거

코사인 유사도는 0 패딩에 영향받지 않는다. 두 벡터가 같은 위치에 같은 길이의 0을 갖는다면

```
cos(a‖0, b‖0) = (a·b + 0) / (‖a‖ · ‖b‖) = cos(a, b)
```

이므로 HNSW 코사인 인덱스의 검색 결과도 동일하다. 저장 공간은 벡터당 1.5KB가
낭비되지만(384 × 4바이트), 인물 수가 수천 명 규모인 이 시스템에서는 무시 가능하다.

**주의**: 서로 다른 차원의 모델로 만든 임베딩을 섞어서 비교하면 안 된다.
128차원 SFace 벡터와 512차원 모델 벡터는 패딩 후에도 의미가 다르다.
`identity_embedding`은 `model_name`·`model_version`을 함께 저장하므로,
프로파일 빌드 시 같은 모델의 임베딩만 집계된다.

## 결과

- §7.2의 모델 교체 시나리오에서 DB 마이그레이션이 필요 없다.
- 512차원 모델로 바꾸면 패딩 없이 그대로 들어간다.
- `dim` 컬럼이 실제 차원을 알려주므로 혼입을 검출할 수 있다.
